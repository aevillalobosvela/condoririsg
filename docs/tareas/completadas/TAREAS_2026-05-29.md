## TAREA 16 — Agregar columna `imagen` a `productos_agro`

### Solicitud del cliente

Agregar soporte de imagen a los productos agropecuarios. La imagen es opcional (NULL en BD) y se usará exclusivamente en la pantalla de ventas POS (`/productosagro/ventas`) para mostrar la imagen del producto en las tarjetas del grid.

---

### Diagnóstico del estado actual

#### Base de datos

La tabla `condoriri.productos_agro` **no tiene columna `imagen`**. Columnas actuales verificadas:

| Columna | Tipo | Nullable |

| id | integer | NO |
| code | varchar(50) | NO |
| producto | varchar(255) | NO |

| sucursal_id | integer | NO |
| user_id | integer | NO |
| estado | boolean | YES |

La tabla de productos lácteos (`condoriri.productos`) sí tiene columna `imagen VARCHAR NULL`.

#### Modelo (`ProductoAgroModel`)

- `$allowedFields` no incluye `imagen`
- `$validationRules` no incluye `imagen`
- El método `getAvailableProducts()` no selecciona `imagen`
- La query raw en `ventasAgroController::register()` tampoco selecciona `imagen`

#### Controlador de productos (`productosAgroController`)

- `store()`: no maneja subida de archivo, el form actual es `method="post"` sin `enctype="multipart/form-data"`
- `update()`: ídem, no maneja imagen
- Patrón de referencia en `productosController` (lácteos): usa `$this->request->getFile('imagen')`, valida tipo y tamaño, mueve a `public/uploads/`, guarda ruta relativa `'uploads/filename.ext'` en BD. Si no se sube imagen, guarda `'jpg'` como placeholder.

#### Vista formulario (`productosAgroFrom.php`)

- `<form>` sin `enctype="multipart/form-data"`
- No tiene campo `<input type="file">` para imagen
- No tiene preview de imagen

#### Vista POS ventas (`productosAgro/ventasIndex.php`)

- Ya implementada la cadena de prioridad de imágenes (TAREA 15)
- Nivel 1 (imagen BD) **no aplica actualmente** porque no existe la columna
- La función `getProductImage(nombre, categoria)` solo recibe 2 parámetros (sin `imagenBD`)
- Una vez agregada la columna, se deberá actualizar esta función para recibir y usar `imagenBD` como nivel 1

### Acciones necesarias

#### 1. Migración de BD

Crear migración CI4 que agregue la columna `imagen` a `condoriri.productos_agro`:

```sql
ALTER TABLE condoriri.productos_agro 
ADD COLUMN IF NOT EXISTS imagen VARCHAR(255) NULL DEFAULT NULL;
```

- Tipo: `VARCHAR(255)` — igual que en `condoriri.productos`
- Nullable: `YES` — la imagen es opcional
- Default: `NULL` — sin placeholder `'jpg'` (a diferencia de productos lácteos, aquí NULL significa "sin imagen")
- Archivo: `app/Database/Migrations/2026-05-29-000001_AddImagenToProductosAgro.php`

#### 2. Modelo (`ProductoAgroModel`)

- Agregar `'imagen'` a `$allowedFields`
- Agregar regla de validación: `'imagen' => 'permit_empty|max_length[255]'`
- Actualizar `getAvailableProducts()` para incluir `productos_agro.imagen` en el SELECT

#### 3. Controlador de productos (`productosAgroController`)

**`store()`:**
- Cambiar `enctype` del form a `multipart/form-data` (en la vista)
- Agregar lógica de subida de imagen después de la validación:
  - Si se subió archivo: validar tipo (jpg/png/gif) y tamaño (máx 2MB), mover a `public/uploads/`, guardar ruta `'uploads/filename.ext'`
  - Si no se subió: guardar `NULL` (no `'jpg'` como en lácteos)
- Agregar `'imagen'` al array `$data` antes del `save()`

**`update()`:**
- Misma lógica de subida
- Si se sube nueva imagen y ya existía una anterior: eliminar el archivo anterior con `@unlink()`
- Si no se sube nueva imagen: no modificar el campo `imagen` (mantener el valor existente)

#### 4. Vista formulario (`productosAgroFrom.php`)

- Agregar `enctype="multipart/form-data"` al `<form>`
- Agregar campo de imagen en la columna derecha (debajo de precios, antes de los botones):
  - `<input type="file" name="imagen" accept="image/*">` — opcional, sin `required`
  - Preview de imagen con `<img id="imagen-preview">`:
    - En edición: mostrar imagen actual si existe (`base_url(producto->imagen)`)
    - En creación: mostrar placeholder gris
  - Texto de ayuda: "Opcional. JPG, PNG o GIF. Máx. 2MB."
- Agregar JS para preview en tiempo real (igual al patrón de `productosform.php`)

#### 5. Vista POS ventas (`productosAgro/ventasIndex.php`)

- Actualizar la query raw en `ventasAgroController::register()` para incluir `pa.imagen` en el SELECT
- Actualizar la función `getProductImage(nombre, categoria)` para recibir un tercer parámetro `imagenBD`:

```js
// Antes
function getProductImage(nombre, categoria) {
  // Nivel 2: imagen local
  // Nivel 4: ícono
}

// Después
function getProductImage(nombre, categoria, imagenBD) {
  // Nivel 1: imagen subida por usuario (BD)
  if (imagenBD && imagenBD !== null) {
    return { type: 'url', src: BASE_URL + imagenBD };
  }
  // Nivel 2: imagen local
  // Nivel 4: ícono
}
```

- Actualizar la llamada en `renderProducts()`:
  ```js
  // Antes
  const img = getProductImage(p.producto, p.categoria);
  // Después
  const img = getProductImage(p.producto, p.categoria, p.imagen ?? null);
  ```

- Agregar constante `BASE_URL` en el bloque de scripts:
  ```js
  const BASE_URL = '<?= base_url() ?>';
  ```

### Decisiones de diseño

| Decisión | Justificación |
|---|---|
| `NULL` en lugar de `'jpg'` como valor por defecto | En agro no hay servidor externo UTO como fallback, NULL es más limpio para distinguir "sin imagen" |
| Subida a `public/uploads/` | Mismo directorio que productos lácteos — consistencia |
| Imagen solo en POS ventas | El cliente no requiere mostrar imagen en el listado de productos agro (`/productosagro`) |
| Validación: máx 2MB, tipos jpg/png/gif | Mismo criterio que productos lácteos |
| Preview en formulario | UX: el operador puede verificar la imagen antes de guardar |
