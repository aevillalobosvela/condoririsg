## TAREA 12 — Inventarios eliminados siguen visibles en `/inventarios`

### Solicitud del cliente

Luego de eliminar un inventario desde `/inventarios/show/{id}`, el registro eliminado
sigue apareciendo en la tabla de `/inventarios`.

---

### Análisis (verificado en BD y código — 2026-05-28)

#### Estado en BD

El soft-delete **funciona correctamente** a nivel de BD:
- 305 registros activos (`deleted_at IS NULL`)
- 6 registros eliminados (`deleted_at IS NOT NULL`)
- El método `deleteUltimoInventario()` llama a `$this->inventarioModel->delete($id)` que
  puebla `deleted_at` correctamente.

#### Causa del problema — `inventariosController::index()`

El modelo `InventarioModel` tiene `useSoftDeletes = true`, lo que hace que `findAll()` y
`paginate()` excluyan automáticamente los registros con `deleted_at IS NOT NULL` **cuando
se usan directamente sobre el modelo**.

Sin embargo, en `index()` se construye el builder así:

```php
$builder = $this->inventarioModel->orderBy('created_at', 'DESC');
```

Al encadenar `orderBy()` directamente sobre `$this->inventarioModel`, CodeIgniter 4
**no siempre aplica el scope de soft-delete** cuando se encadenan métodos antes de
`findAll()` o `paginate()`. El scope se aplica correctamente solo cuando el builder
parte limpio desde el modelo.

Adicionalmente, la rama de filtros personalizados usa `getFilteredInventarios()`:

```php
$inventarios = $this->inventarioModel->getFilteredInventarios($nombre, $fecha_inicio, $fecha_fin);
```

Hay que verificar que este método también excluya `deleted_at IS NOT NULL`.

#### Solución

Agregar `->where('deleted_at', null)` explícitamente en el builder de `index()` para
garantizar que los registros eliminados nunca aparezcan, independientemente de cómo
CI4 aplique el scope interno:

```php
$builder = $this->inventarioModel
    ->where('deleted_at', null)
    ->orderBy('created_at', 'DESC');
```

Y verificar/corregir `getFilteredInventarios()` en el modelo.
