### CAMBIO 1 — Indicador de cliente seleccionado en POS contado

#### Estado actual

En las 3 vistas de contado, al seleccionar un cliente del dropdown `#clientResults`, la función `selectClient()` hace:
- Rellena `#clientSearch` con el nombre
- Rellena `#clienteIdInput` (hidden) con el id
- Cierra el dropdown
- Opcionalmente muestra `#clientEditPanel` si el cliente es del usuario hoy

**No hay ningún indicador visual de confirmación** — el operador no sabe con certeza qué cliente quedó seleccionado una vez que el dropdown se cierra.

#### Estado en vistas de crédito (referencia)

En las 3 vistas de crédito, al seleccionar un receptor, `#personalInfo` se rellena con:

```html
<div class="alert alert-success py-2">
  <strong>Seleccionado:</strong> NOMBRE — DIP: 12345678
  <span class="badge bg-primary ms-2">UTO</span>  <!-- o bg-warning para externo -->
</div>
```

Este patrón es claro, consistente y ya conocido por el operador.

#### Solución

Agregar un `<div id="clienteSeleccionadoInfo" class="mt-2"></div>` debajo del `#clientResults` en las 3 vistas de contado. En la función `selectClient()`, al seleccionar un cliente, rellenar este div con el mismo patrón `alert-success`:

```html
<div class="alert alert-success py-2 mb-0">
  <i class="ri-user-check-line me-1"></i>
  <strong>Cliente:</strong> NOMBRE — CI: 12345678
</div>
```

Al limpiar el input o cancelar la venta, vaciar el div.

**Casos especiales:**
- "Consumidor Final" (id=0, sin cliente): mostrar badge neutro `alert-secondary` con texto "Consumidor Final — sin CI registrado"
- Al cancelar venta: limpiar `#clienteSeleccionadoInfo`

### CAMBIO 2 — Tamaños de fuente en tarjetas de producto

#### Estado actual (los 3 módulos)

En las tarjetas de producto del grid POS, los tamaños actuales son:

| Elemento | Tamaño actual |
|---|---|
| Nombre del producto | `0.8rem` (ventas/inventarios) / `0.82rem` (agro) |
| Precio (`Bs. X.XX`) | `0.9rem` (ventas/inventarios) / `0.85rem` (agro) |
| Stock (badge) | `0.65rem` (ventas/inventarios) / `0.62rem` (agro) |

El stock es el dato más operativamente crítico en el POS (el operador necesita saber de un vistazo si hay unidades disponibles), pero actualmente es el elemento más pequeño de la tarjeta.

#### Solución

Nuevos tamaños para los 3 módulos (unificados):

| Elemento | Tamaño nuevo | Cambio |
|---|---|---|
| Nombre del producto | `0.82rem` | Sin cambio significativo |
| Precio (`Bs. X.XX`) | `0.88rem` | Ligero aumento |
| Stock (número + unidad) | `1.05rem`, `font-weight: 700` | Aumento notable, negrita |

El stock deja de ser un `badge` pequeño y pasa a ser texto prominente con color del producto:

```html
<!-- Antes -->
<span class="badge" style="background-color: ${colors.border}; font-size: 0.65rem;">
  ${stock} und
</span>

<!-- Después -->
<div style="font-size: 1.05rem; font-weight: 700; color: ${colors.badge}; line-height: 1;">
  ${stock}
  <span style="font-size: 0.72rem; font-weight: 400; color: ${colors.text};">und</span>
</div>
```

#### Decisión del cliente — Cadena de prioridad de imágenes

La lógica de resolución de imagen para cada tarjeta de producto sigue esta cadena de prioridad, de mayor a menor:

```
1. Imagen subida por el usuario (campo `imagen` en BD, distinto de 'jpg')
   ↓ si no existe
2. Imagen local por nombre normalizado (public/assets/img/{nombre-normalizado}.{ext})
   ↓ si no existe
3. Imagen del servidor externo UTO (mecanismo actual con probeImage)
   ↓ si no existe
4. Ícono Remix Icon representativo por categoría (fallback visual, sin imagen)
```

---

#### Implementación definida

##### Nivel 1 — Imagen subida por usuario

El controller ya pasa el campo `imagen` en el JSON de productos. En el POS, al renderizar una tarjeta, si `p.imagen` existe y no es `'jpg'`, usar `base_url + p.imagen` como URL de imagen.

**Aplica a:** módulos lácteos (ventas + inventarios). No aplica a agro (sin columna `imagen`).

##### Nivel 2 — Imagen local por nombre normalizado

Mapa JS de nombre de producto → ruta local en `public/assets/img/`. La normalización del nombre sigue la convención de los archivos ya subidos: minúsculas, espacios reemplazados por guiones, sin caracteres especiales.

```js
const LOCAL_IMAGE_MAP = {
  'QUESO 900 GRAMOS':         '<?= base_url('assets/img/queso-900-gramos.png') ?>',
  'QUESO SIN SAL 500 GRAMOS': '<?= base_url('assets/img/queso-sin-sal-500-gramos.png') ?>',
  'YOGURT 1 LITRO':           '<?= base_url('assets/img/yogurt-1-litro.jpg') ?>',
  'YOGURT GRIEGO 250 GRAMOS': '<?= base_url('assets/img/yogurt-griego-250-gramos.jpg') ?>',
  // Agregar más a medida que se suban archivos
};
```

Cuando se suba una imagen nueva a `public/assets/img/`, solo hay que agregar la entrada al mapa — sin cambios en BD ni en controllers.

**Aplica a:** los 3 módulos (ventas, inventarios, agro).

##### Nivel 3 — Imagen del servidor externo UTO

El mecanismo actual (`IMAGE_MAP` numérico + `probeImage` + `resolveAllImages`) se conserva **sin cambios** como tercer nivel de fallback.

**Aplica a:** módulos lácteos (ventas + inventarios). El módulo agro no tiene este mecanismo actualmente.

##### Nivel 4 — Ícono Remix Icon por categoría

Si ninguno de los niveles anteriores resuelve una imagen, en lugar del círculo con 2 iniciales se muestra un ícono Remix Icon representativo:

| Categoría / patrón de nombre | Ícono |
|---|---|
| Contiene `LECHE` | `ri-drop-line` |
| Contiene `QUESO` | `ri-cake-2-line` |
| Contiene `YOGURT` o `LACTOFRUT` | `ri-cup-line` |
| Contiene `REQUESON` | `ri-bowl-line` |
| Agro: `TUBERCULOS` | `ri-plant-line` |
| Agro: `HORTALIZAS` | `ri-leaf-line` |
| Agro: `CEREALES` | `ri-seedling-line` |
| Agro: `LEGUMINOSAS` | `ri-seedling-line` |
| Agro: `DESHIDRATADOS` | `ri-sun-line` |
| Cualquier otro | `ri-shopping-basket-line` |

El ícono se renderiza dentro del círculo de color existente, reemplazando las 2 iniciales.

#### Lógica de resolución en JS (pseudocódigo)

```js
async function resolveProductImage(producto) {
  // Nivel 1: imagen subida por usuario (solo módulos lácteos)
  if (producto.imagen && producto.imagen !== 'jpg') {
    return { type: 'url', src: BASE_URL + producto.imagen };
  }

  // Nivel 2: imagen local por nombre
  const localUrl = LOCAL_IMAGE_MAP[producto.nombre?.toUpperCase().trim()];
  if (localUrl) {
    return { type: 'url', src: localUrl };
  }

  // Nivel 3: imagen servidor externo UTO (probeImage existente)
  const num = IMAGE_MAP[producto.nombre?.toUpperCase().trim()];
  if (num && resolvedImages[num]) {
    return { type: 'url', src: resolvedImages[num] };
  }

  // Nivel 4: ícono por categoría
  return { type: 'icon', icon: getCategoryIcon(producto.nombre, producto.categoria) };
}
```

La función `renderProducts()` usa el resultado para decidir si renderiza `<img>` o `<i class="ri-...">`.
