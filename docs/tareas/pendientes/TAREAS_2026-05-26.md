## TAREA 2 — Orientación horizontal (landscape) en reportes PDF de ventas

### Solicitud del cliente

Los reportes PDF de ventas matriciales actualmente se generan en formato A4 vertical (portrait).
Con la columna "Categoría" agregada en la Tarea 1, el ancho disponible (190mm con márgenes 10mm)
es insuficiente para mostrar todos los datos con legibilidad. Se requiere cambiar a A4 horizontal
(landscape, 277mm de ancho útil).

---

### Archivos a modificar

| Archivo | Cambio | Detalle |
|---|---|---|
| `app/Libraries/CierreVentaPdf.php` | `AddPage('P', 'A4')` → `AddPage('L', 'A4')` | Tienda CEAC — también en `AddPage()` de salto de página |
| `app/Libraries/CierreVentaInve.php` | `AddPage('P', 'A4')` → `AddPage('L', 'A4')` | Planta lácteos — también en `AddPage()` de salto de página |
| `app/Libraries/Agro/CierreVentaAgroPdf.php` | `AddPage('P', 'A4')` → `AddPage('L', 'A4')` | Agro — también en `AddPage()` de salto de página |

Los tres archivos comparten la misma lógica de cálculo de anchos. Al pasar a landscape,
`$this->GetPageWidth()` devuelve 297mm en lugar de 210mm, por lo que los anchos de columna
se recalculan automáticamente sin cambios adicionales en la fórmula existente:

```php
// Fórmula actual — funciona igual en landscape porque usa GetPageWidth() dinámicamente
$colWidth = $numProds > 0
    ? min(25, ($this->GetPageWidth() - 20 - $wNro - $labelWidth - $wFijos) / $numProds)
    : 25;
```

**Ajuste adicional necesario:** el `labelWidth` (columna "APELLIDOS Y NOMBRES") puede
ampliarse de 50mm a 65mm para aprovechar el espacio extra y mejorar la legibilidad de
nombres largos.

#### JOIN completo verificado en producción

```sql
SELECT p.nombre, p.dip,
       te.tipo_empleado,   -- ← categoría laboral
       c.cargo,            -- ← cargo específico
       s.seccion           -- ← sección/facultad
FROM public.personas p
JOIN rrhh.empleados e      ON e.id_persona = p.id_persona AND e.id_estado = true
JOIN rrhh.tipos_empleados te ON te.id_tipo_empleado = e.id_tipo_empleado
JOIN rrhh.cargos c         ON c.id_cargo = e.id_cargo
JOIN rrhh.secciones s      ON s.id_seccion = e.id_seccion
```

Resultado verificado con ventas reales:
- `ADMINISTRATIVO` → cargo "SECRETARIO I", "AUXILIAR CONTABILIDAD", etc.
- `DOCENTE TC` → cargo "DOCENTE UNIVERSITARIO TIEMPO COMPLETO"

#### Ventas a crédito en producción

- La gran mayoría usa `personal_uto_id` (personal UTO)
- Un subconjunto usa `cliente_externo_id` (externos: Seguro Univ., Spectrolab, Otros)
- Ninguna venta a crédito usa `cliente_id` (ese campo es exclusivo de contado)
